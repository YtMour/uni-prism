# DiceForge 构建计划

## 构建原则

DiceForge 应先打通完整生成闭环，再做动效和视觉强化。每个阶段都必须产出用户可见能力，并同步更新状态文档。

## 当前阶段状态

当前已完成 Phase 0 到 Phase 4 的 H5 MVP 主线能力，处于 H5 MVP 发布候选加固阶段。Phase 5 仍是后续扩展方向，不进入当前 MVP 发布承诺。

| 阶段 | 当前状态 | 说明 |
| --- | --- | --- |
| Phase 0 文档和数据准备 | Done | 产品、规则、UX、数据结构、构建计划和文档索引已建立 |
| Phase 1 角色生成 MVP | Done | 生成器、seed、4d6、职业友好属性、去重和故事生成已实现 |
| Phase 2 角色卡 UI | Done | 首页、生成中、角色卡、重掷、复制、导出和最近列表已覆盖 |
| Phase 3 导出和本地记录 | Done | 文本复制、海报预览和最近角色记录已实现；PNG 保存暂缓 |
| Phase 4 动效和体验打磨 | Done | 中心 D20 使用透明 premium 图片和短投骰动效，H5 smoke 已覆盖关键标记 |
| Phase 5 扩展能力 | Deferred | 批量 NPC、锁定字段、Homebrew、多语言和 PDF 不进入 MVP |

发布门槛以 [MVP_RELEASE_CHECKLIST.md](./MVP_RELEASE_CHECKLIST.md) 为准。

## Phase 0: 文档和数据准备

目标：把产品、规则、数据和设计边界固定下来。

交付物：

- README 文档入口。
- 产品规格。
- 规则规格。
- 生成系统设计。
- UX 设计规范。
- 数据结构设计。
- 实现状态追踪。

验收标准：

- 后续开发者能根据文档直接开始实现 MVP。
- MVP 范围和暂缓范围明确。
- 数据模型足够支撑角色卡、复制文本和海报导出。

## Phase 1: 角色生成 MVP

目标：完成无后端、可本地运行的角色生成核心。

交付物：

- 种族、职业、背景、阵营数据源。
- seed 随机上下文。
- 4d6 去最低属性生成。
- 属性修正值计算。
- 职业友好属性分配。
- 熟练项和装备合并去重。
- 三句话背景故事生成。

验收标准：

- 点击生成后得到完整角色。
- 所有字段非空。
- 属性修正值计算正确。
- 同 seed 可复现同一角色。

## Phase 2: 角色卡 UI

目标：完成第一版可用界面。

交付物：

- 首页 D20 生成入口。
- 响应式角色卡。
- 生成、重掷、复制按钮。
- 复制成功/失败反馈。
- 移动端基础布局。

验收标准：

- 移动端和桌面端均可读。
- 10 秒内完成首次生成。
- 复制内容可直接粘贴到聊天工具。

## Phase 3: 导出和本地记录

目标：让用户能保留和分享角色。

交付物：

- 纯文本导出格式稳定。
- 海报预览基础版。
- 最近一次角色本地保存。
- seed 显示和复制。

验收标准：

- 刷新页面后能恢复最近角色。
- 海报预览文字不截断、不重叠。
- 导出内容包含核心角色信息。

## Phase 4: 动效和体验打磨

目标：提升生成仪式感，但不牺牲可用性。

交付物：

- D20 点击动效。
- 生成时短暂过渡状态。
- 移动端触感反馈。
- 局部重掷能力。
- 空状态和错误状态打磨。

验收标准：

- 动效不超过 1200ms。
- 快速点击不会导致状态错乱。
- 低性能设备仍可完成生成。

## Phase 5: 扩展能力

候选方向：

- 批量生成 NPC。
- 锁定字段后重掷。
- Homebrew 数据导入。
- 更多种族、职业、背景。
- 多语言输出。
- 打印友好的 PDF。

这些能力不进入 MVP，除非前四个阶段已经稳定。
