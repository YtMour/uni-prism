# DiceForge UX 设计规范

## 设计目标

DiceForge 的视觉目标是“现代、克制、带有复古奇幻气味”。它不应看起来像复杂表单，也不应变成重装饰的游戏界面。用户第一眼应该看到角色，而不是规则。

## 信息层级

角色卡信息按优先级展示：

1. 名字、种族、职业
2. 阵营与背景
3. 六项属性
4. 熟练项和装备
5. 三句话背景故事
6. seed 和复制/导出操作

## 首页结构

首页由三个区域组成：

- 顶部：应用名称和最小操作区。
- 中央：D20 生成入口。
- 下方：最近生成角色或空状态。

首页不做营销页，不放大段介绍。打开应用后，用户应立即能点击生成。

## D20 交互

D20 是核心交互入口，承担“生成按钮”的角色。

交互要求：

- 默认静止状态有轻微高光。
- hover 或按压时出现可见反馈。
- 点击后进入 600ms 到 1200ms 的生成动效。
- 动效结束后角色卡内容更新。
- 移动端支持清脆的触感反馈。

动效不应阻碍连续生成。若用户快速重复点击，应节流或排队处理。

## 角色卡布局

### 移动端

- 单列布局。
- 顶部固定角色身份。
- 六项属性使用 2 列或 3 列网格。
- 操作按钮靠近底部，但不遮挡内容。

### 桌面端

- 主卡片居中，最大宽度受控。
- 左侧展示身份与背景故事。
- 右侧展示属性、装备和熟练项。
- 避免多层卡片嵌套。

## 视觉系统

### 颜色

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--color-blood` | 主交互色 | `#4A1515` |
| `--color-ink` | 主文字 | `#191512` |
| `--color-parchment` | 页面背景 | `#F3E7CF` |
| `--color-brass` | 强调线条 | `#A47A3B` |
| `--color-stone` | 次要文字 | `#6D6257` |
| `--color-panel` | 内容面板 | `#FFF8EA` |

注意：整体不能只依赖棕色和米色。应通过暗红、墨色、铜色和留白形成对比。

### 字体

- 数值、按钮、标签：Montserrat 或系统无衬线。
- 背景故事：Lora 或系统衬线。
- 中文环境下使用系统中文字体兜底。

推荐 CSS 字体栈：

```css
--font-display: "Montserrat", "Inter", system-ui, sans-serif;
--font-story: "Lora", "Noto Serif SC", serif;
--font-ui: "Inter", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

## 操作设计

主要操作：

- Generate：生成角色。
- Reroll：重新生成完整角色。
- Copy：复制文本。
- Export：导出海报。

次要操作：

- Reroll Story：只重写背景故事。
- Reroll Stats：只重掷属性。
- Lock Field：后续版本支持锁定字段。

## 复制反馈

复制成功后显示短反馈：

```text
Copied
```

反馈时间建议为 1200ms 到 1800ms。失败时应说明浏览器权限或环境限制。

## 海报导出

海报导出应优先保持信息完整：

- 角色名和职业必须显著。
- 六项属性必须可读。
- 背景故事最多三句话。
- seed 可放在底部小字。
- 不用复杂纹理影响文字可读性。

MVP 可先导出 PNG，后续再支持不同尺寸。

## 可访问性

- 所有按钮必须有明确文本或 aria-label。
- 颜色对比度应满足常规可读性。
- 生成结果不能只依赖颜色表达。
- 键盘可触发 Generate 和 Copy。
