## Phase 1：核心换算 MVP

目标：完成可信的汇率换算闭环。

- [x] 从当前 `pages/index/index.vue` 中抽离 mock 货币表和换算函数。
- [x] 实现以 `USD` 为基准的汇率矩阵转换。
- [x] 支持任意一个币种作为输入基准，并选择一个目标币种实时换算。
- [x] 使用 `Intl.NumberFormat` 按 locale 格式化金额。
- [x] 支持本币、关注币种和输入金额的本地状态。
- 实现货币选择、关注币种排序和默认币种恢复。

验收：

- [x] 覆盖 `A -> B = R_B / R_A` 的核心计算验证。
- [x] 大金额、小数、零值、无效输入有明确处理。
- 切换输入基准不导致循环更新或精度异常。
- 刷新页面或重启 App 后保留用户设置。

## Phase 2：汇率缓存与离线模式

目标：让旅行场景下的核心功能断网可用。

- 先实现 mock rate adapter，保留真实 API adapter 接口。
- 评估并选择真实汇率数据源，再接入生产 adapter。
- 缓存最近一次有效汇率、更新时间和数据源。
- 实现按需过期策略，刷新失败时回退缓存。
- UI 明确展示数据新鲜度和离线状态。

验收：

- 联网刷新成功后能断网继续换算。
- 无缓存首次打开时有明确空状态。
- API 失败不会清空可用旧数据。

## Phase 3：旅行计算器

目标：补齐出境消费刚需。

- 支持税率、常用小费比例、自定义小费。
- 支持 AA 分摊人数。
- 输出外币总价、本币总价和人均金额。
- 支持保存常用国家或地区税率模板。

验收：

- 税费、小费、分摊计算可独立验证。
- 计算结果与核心汇率模块共用格式化逻辑。
- 离线状态下功能完整可用。

## Phase 4：体验、i18n 与上架准备

目标：把 MVP 打磨到可试用。

- [x] 建立多语言资源：简体中文、英文。
- 后续再扩展西班牙语、法语、德语、日语。
- [x] 增加语言选择设置。
- 语言选择持久化仍待接入。
- 做长文本布局检查，避免德文、法文扩展后错位。
- 补充隐私政策、权限声明、应用商店文案。

验收：

- 语言切换后关键页面无文本溢出。
- 权限声明与实际调用能力一致。
- 文档中不再有与当前实现冲突的描述。

## 延后范围

以下功能不建议进入首个 MVP：

- AI 拍照标价换算。
- AR 价格覆盖。
- iOS / Android 桌面小组件。
- 账号系统、云同步、真实支付订阅。
- 历史汇率图表与复杂资产盯盘。
