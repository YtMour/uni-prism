# RateLens 功能设计

本文档用于把 README 中的产品愿景拆成可实施功能。当前优先级以 MVP 为准，延后功能只保留边界，不进入首轮开发。

## 信息架构

RateLens 首版建议保留 3 个主入口：

| 页面 | 目标 | MVP 必要性 |
| --- | --- | --- |
| 汇率换算首页 | 输入金额，选择源货币和目标货币，查看单笔换算结果与汇率更新时间 | 必须 |
| 旅行计算器 | 税率、小费、AA 分摊，输出本币总价 | 必须 |
| 设置 | 本币、关注币种、语言、缓存和隐私入口 | 必须 |

后续页面：

- 汇率趋势：延后到有历史数据后。
- Lens Scanner：延后到 OCR 与权限策略明确后。
- 小组件管理：延后到 App 端稳定后。

## 汇率换算首页

### 用户目标

用户打开 App 后，应在 3 秒内完成一个金额的跨币种估算。

### 核心控件

- 金额输入区：显示当前输入币种、金额和清除入口。
- 目标货币选择：用户直接选择转换后的币种，首页只展示当前换算结果。
- 数据状态条：显示最近更新时间、离线状态、刷新入口。
- 货币管理入口：添加、移除、排序常用候选币种。

### 关键交互

- 输入金额时，目标货币结果实时刷新。
- 用户可交换源货币和目标货币。
- 无网络但有缓存时，继续换算并显示“使用缓存汇率”。
- 无缓存时，首页不展示错误堆栈，只展示可理解的空状态和重试入口。

### 状态设计

| 状态 | UI 行为 |
| --- | --- |
| 首次打开无缓存 | 展示默认币种列表和“需要联网获取汇率” |
| 汇率刷新中 | 保留旧数据，刷新入口进入 loading |
| 刷新成功 | 更新金额、更新时间和缓存 |
| 刷新失败有缓存 | 保留旧数据，提示正在使用缓存 |
| 刷新失败无缓存 | 禁用换算结果，提示重试 |

## 旅行计算器

### 用户目标

用户在餐厅或商店输入外币账单后，快速得到含税、小费和人均本币金额。

### 输入项

- 原始金额。
- 消费币种。
- 税率：默认 0%，支持自定义。
- 小费：0%、10%、15%、18%、20%、自定义。
- 分摊人数：默认 1，最小 1。

### 输出项

- 外币小计。
- 外币含税价。
- 外币含税含小费总价。
- 本币总价。
- 本币人均金额。

### 计算顺序

1. `taxAmount = subtotal * taxRate`
2. `tipBase = subtotal + taxAmount`
3. `tipAmount = tipBase * tipRate`
4. `totalForeign = subtotal + taxAmount + tipAmount`
5. `totalHome = convert(totalForeign, foreignCurrency, homeCurrency)`
6. `perPersonHome = totalHome / peopleCount`

## 设置

### 必须设置项

- 本币。
- 关注币种。
- 语言。
- 汇率缓存状态与手动刷新。
- 隐私说明入口。

### 建议默认值

- 本币：跟随系统 locale 推断，无法推断时使用 `USD`。
- 默认关注币种：`USD`、`EUR`、`JPY`、`GBP`、`CNY`、`HKD`；更多可选币种包括 `AUD`、`CAD`、`SGD`、`CHF`、`KRW`、`THB`、`MYR`、`TWD`、`INR`、`AED`。
- 语言：跟随系统，首版至少支持 `zh-CN` 和 `en-US`。
- 汇率过期阈值：默认 12 小时，超过后尝试后台刷新。

## 延后功能设计边界

### Lens Scanner

首版不实现。后续进入时必须先明确：

- OCR 本地还是云端。
- 相机权限文案。
- 是否上传图片。
- 识别失败时是否允许手动校正。
- 免费额度和付费成本。

### 桌面小组件

首版不实现。后续进入时必须先验证：

- uni-app 对 iOS/Android 小组件的可行路径。
- 数据刷新频率限制。
- 缓存数据如何同步到小组件。
- 小组件是否只展示汇率，不允许输入金额。

## MVP 验收口径

- 用户能完成从金额输入到单笔目标货币结果的完整流程。
- 用户能断网使用最近一次缓存汇率。
- 用户能完成餐厅账单的小费、税费和 AA 分摊。
- 用户能切换语言、本币和关注币种。
- 文档、页面和实现状态保持一致。
