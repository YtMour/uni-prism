# CampPack 路线图

## Phase 0: 文档与范围冻结

目标：把 README 中的产品愿景拆成可执行规格。

交付：

- README 项目入口。
- 产品规格。
- 设计系统。
- 技术方案。
- 实现状态。
- QA 清单。

验收：

- MVP 范围清晰。
- 暂缓功能明确。
- 后续开发可以直接按文档拆任务。

## Phase 1: 工程基础

目标：创建可运行的 uni-app 项目骨架。

任务：

- 初始化 Vue 3 + Vite + uni-app 工程。
- 配置 Pinia。
- 建立路由页面: 清单列表、模板、详情、设置。
- 建立主题变量和基础布局。
- 建立本地 storage repository。

验收：

- H5 能启动。
- App 构建入口可用。
- 空数据状态能展示。
- 设置页能读写单位系统。

## Phase 2: MVP 清单闭环

目标：用户能创建、导入、清点并持久化一份露营清单。

任务：

- 内置 3 套模板。
- 支持创建、重命名、复制、删除清单。
- 支持分类与装备条目 CRUD。
- 实现 Pack / Setup / Leave 模式切换。
- 实现 Leave 反向清点初始化。
- 实现重量统计和单位切换。

验收：

- 从模板导入清单后可完成三阶段清点。
- 重启 App 后状态保留。
- 断网时不影响核心流程。
- 删除和重置操作有确认。

## Phase 3: 可用性打磨

目标：提升真实户外使用体验。

任务：

- 搜索与筛选。
- 分类折叠。
- 关键装备标记。
- 勾选触觉反馈。
- 长清单性能优化。
- 数据导出 JSON。

验收：

- 300 条装备列表仍可顺畅勾选。
- 户外强光下关键状态可辨。
- 数据可导出并重新导入验证。

## Phase 4: 发布准备

目标：准备首个可测试版本。

任务：

- App 图标和启动图。
- 隐私政策。
- 商店文案。
- 手工测试矩阵。
- 崩溃和数据异常兜底。

验收：

- iOS / Android 真机完成 smoke。
- 无核心权限滥用。
- 本地数据迁移路径可验证。

## Phase 5: Pro 与增长

目标：验证商业化和高级用户需求。

候选功能：

- 自定义模板保存。
- 模板分享。
- 云备份。
- 跨设备同步。
- 多人协作清点。
- 专业模板包。
- 装备价格 / 预算统计。
- 行程天气辅助。

进入条件：

- MVP 用户能稳定完成核心清点。
- 已有明确用户反馈指向高级需求。
- 数据模型和本地迁移稳定。
